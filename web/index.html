CONCEPT LIBRARY

Four ideas, four working demonstrations

Directly from the Eigensight research framework. Each pipeline stage has an authentic working visualization of the exact physical mechanism it relies on.

STAGE 01 · SEMANTIC SEGMENTATION

Classifying every point as static or dynamic

Point clusters are labeled frame by frame and temporally stacked to confirm the label holds over time. The tree, wall, and red car stay static throughout; the yellow object is reclassified to dynamic the moment it starts moving. This is the raw output of pipeline stage 01, before anything is projected into a grid.

static: tree, wall, red car dynamic: cyan car
STAGE 02 · TERRAIN-AWARE STACKING

The same classification, now against real ground

Identical object classes, but placed on textured terrain — grass either side of a dirt path — instead of an empty black plane. It's the check for stage 01 of the terrain-analysis task: can the model still separate static and dynamic objects cleanly once the drivable surface itself is noisy and visually busy underneath them?

terrain: grass, dirt path static: tree, wall, red car dynamic: cyan car
STAGE 03 · VARIABLE-RESOLUTION GRID

Coarse globally, fine where it matters

The non-uniform grid itself: a 10m coarse cell spans the full scene, while a 5cm local grid overlays the region immediately around the objects of interest. This is the literal foveation mechanic from the project background — precision spent near the sensor, cost saved everywhere else.

global: 10m coarse cells local: 5cm fine cells
STAGE 04 · 3D → 2.5D HEIGHT COLLAPSE

Flattening volume onto the ground plane, without losing it

3D point volumes get dropped onto the flat XY plane one occupied cell at a time. Inside 10m, the local 5cm grid keeps individual cells; beyond it, points fall back to sparse dots while the cell still retains mean height, standard deviation, and variance — so elevation isn't discarded, just compressed as distance grows. This is stage 02 of the pipeline in motion.

static: red car dynamic: cyan car
GRID SPECIFICATION

Resolution falls off the way it should — gradually, and by design

0m — near field10m100m — far field
ZoneRadiusCell sizeElevation Statistics
Near field (Fovea)0 – 10m5cmMean (μz), Variance (σz²), StdDev (σz)
Far field (Horizon)10 – 100m50cmStrictly Binary Occupied vs Free (1 / 0)

The engine maintains this spatial gradient without alignment errors at zone boundaries or data loss when multiple points fall into a coarsened far-field cell — both are correctness requirements, not just performance ones.

Evaluation targets two things directly: 98.0% memory reduction against a uniform high-resolution 3D baseline, and classification accuracy by distance band on 7,000 picture scenes.

Latency is reported in FPS, measured end-to-end from raw point cloud to rendered dashboard frame.
